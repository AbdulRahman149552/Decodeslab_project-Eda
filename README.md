# E-Commerce Sales - Exploratory Data Analysis

Exploratory data analysis (EDA) on an e-commerce orders dataset: cleaning messy raw data, then digging into revenue, product, payment, referral, and customer trends. Built as Project 2 for the DecodeLabs data analytics program.

##  Overview

The raw dataset arrives with the usual real-world problems — duplicate orders, numeric columns stored as text, coupon codes mixed into a price column — and this notebook walks through diagnosing and fixing those issues before moving into analysis. The end goal is a clean dataset (`clean_data.csv`) and a set of business-relevant insights on sales performance.

##  Dataset

**File:** `Dataset_for_Data_Analytics.xlsx`
**Rows / Columns:** 1,200 orders × 14 columns

| Column | Description |
|---|---|
| `OrderID` | Unique order identifier |
| `Date` | Order date |
| `CustomerID` | Unique customer identifier |
| `Product` | Product purchased (e.g. Monitor, Phone, Tablet, Chair, Printer) |
| `ShippingAddress` | Shipping address |
| `PaymentMethod` | Payment method used (Debit Card, Credit Card, Online, etc.) |
| `OrderStatus` | Order status (Shipped, Delivered, Cancelled, Returned) |
| `TrackingNumber` | Shipment tracking number |
| `CouponCode` | Coupon applied at checkout (if any) |
| `ReferralSource` | Channel that referred the order (Instagram, Facebook, Email, Referral, etc.) |
| `TotalPrice` | Final order total |
| `Quantity` | Units ordered |
| `UnitPrice` | Price per unit |
| `ItemsInCart` | Number of items left in the cart |

## Data Cleaning

Key issues identified and resolved in the notebook:

- **Duplicate orders** — some `OrderID`s appeared more than once; duplicates were dropped, keeping the first occurrence.
- **Mixed-type numeric columns** — `Quantity` and `UnitPrice` contained non-numeric values (e.g. `"SAVE10"`, `"Referral"`) mistakenly entered in those fields; these were coerced to numeric with invalid entries converted to `NaN`.
- **Consistency check** — a `CalculatedTotal` (`Quantity × UnitPrice`) was derived and compared against the given `TotalPrice` to flag pricing discrepancies.
- **Date features** — `Date` was used to derive `Year`, `Month`, `MonthName`, and `YearMonth` for time-based analysis.
- **Outlier & sanity checks** — reviewed unusually high `ItemsInCart` values and negative quantities.

## Analysis & Visualizations

The notebook covers:

- **Sales overview** — total orders, total revenue, average order value, total/average quantity sold
- **Product performance** — revenue and average order value by product
- **Order status breakdown** — counts and percentages (Shipped / Delivered / Cancelled / Returned)
- **Payment methods** — order counts and revenue by payment method
- **Referral sources** — order counts and revenue by acquisition channel
- **Coupon impact** — order count, total, and average revenue by coupon code
- **Time trends** — monthly revenue and monthly order volume (line charts)
- **Distribution & outliers** — histogram and boxplot of order values
- **Relationships** — quantity vs. total price, items-in-cart vs. total price (scatter plots), and a correlation matrix of numeric fields
- **Customer analysis** — top customers by order count and by revenue

##  How to Run

1. Clone the repo and install dependencies:
   ```bash
   pip install pandas numpy matplotlib openpyxl jupyter
   ```
2. Make sure `Dataset_for_Data_Analytics.xlsx` is in the same directory as the notebook.
3. Open and run the notebook:
   ```bash
   jupyter notebook EDA.ipynb
   ```
4. The cleaned dataset is exported at the end as `clean_data.csv`.

##  Key Takeaways

- Revenue and order volume were tracked month over month to surface seasonal trends.
- A handful of products and referral channels account for a disproportionate share of revenue.
- Data quality issues (duplicated orders, mistyped numeric fields) were significant enough that cleaning was a required first step before any analysis could be trusted.
